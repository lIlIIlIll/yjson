# 从 0.1.x 迁移到 0.2.0 候选

`0.2.0` 仍是开发候选。本次不发布 yjson 包或 tag；实现与验证状态见
[实施记录](../implementation/cjdoc-020.md)。

整个 `0.x` 的 patch 和 minor 不保证跨版本源码、API、ABI、宏生成代码或旧 SDK 兼容。
升级时同步第一方包，重新展开宏并重新编译应用。破坏性 API 修改仍需单独确认，不能仅凭
本政策删除接口或改变输入输出语义。

## 更新工具链和依赖

1. 使用 Cangjie STS `1.2.0` 与匹配的 stdx。
2. 将使用的第一方包同步到同一批 `0.2.0` 候选，使用最终验证的宏仓提交。
3. 更新消费方锁文件，重新编译全部生成代码和应用，再运行应用的序列化与错误处理测试。

不要混用旧版编译产物。当前生成协议与 C ABI 校验继续执行；它们用于发现错配，不能证明
任意两个版本可以混用。包图和当前 SDK 约束见[发布流程](../maintainers/releasing.md)。

## 替换已删除的宏

已批准删除 `@JsonValue` 宏别名，不保留转发入口。将旧调用：

```cangjie
let value = @JsonValue({"enabled": true})
```

改为：

```cangjie
let value = @Json({"enabled": true})
```

运行时树类型仍是 `JsonNode`。字段读取别名 `@JsonAlias`、集合展开别名和当前生成协议
保持现有职责，不属于本次删除范围。

## 更新文档消费方

重新生成并使用九包统一站点。机器消费方使用 Doc IR v16 和完整 Agent 离线包；同步更新
查询命令和产物路径。新站点不提供旧 URL 重定向、旧 Doc IR 适配或旧目录布局兼容层。
生成与验证方法见[API 文档指南](../maintainers/api-documentation.md)。

## 回退

需要回退时恢复整批第一方依赖、原锁文件和对应 SDK，重新生成并编译应用。不要只替换一个
运行库或沿用新版本生成的二进制。回退后重新验证应用的真实输入、输出、预算和错误处理。
